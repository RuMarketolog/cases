# 🟢 Изменения портфолио — 14.10.2026

## Счётчик Яндекс Метрики на хабе «Кейсы»

По просьбе владельца в аккаунте Метрики `rumarketolog@yandex.ru` создан отдельный
счётчик **113625003** «Кейсы — rumarketolog.github.io/cases» и установлен на хаб.

### Что изменено

- В `Кейсы.html` добавлен код счётчика: скрипт `tag.js` — перед `</head>`,
  `<noscript>`-пиксель — сразу после `<body>`. Код взят из API Метрики (поле `code`
  счётчика), служебный параметр `isFromApi` убран.
- Включены: вебвизор, карта кликов, отслеживание внешних ссылок, точный показатель
  отказов. Часовой пояс счётчика — Москва, фильтр роботов включён.
- `index.html` и `cases.html` синхронизированы с `Кейсы.html` (SHA-256 трёх файлов
  совпадает), поэтому счётчик стоит и на главной `rumarketolog.github.io/cases/`.
  Сначала код был поставлен только в `Кейсы.html` (коммит `70956c6`), копии догнаны
  при «сохрани».

### Почему так

- 🟡 **Метрика привязывает счётчик к домену, а не к папке.** Счётчик создан на
  `rumarketolog.github.io` — тот же домен, что у страницы департамента маркетинга
  (её счётчик — `113625002`). Данные не смешиваются, потому что каждая страница
  несёт код только своего счётчика.
- 🔴 **Страницы `hh.ru.html`, `ИТ-компания.html`, `Стоматологическая клиника.html`
  и их латинские алиасы счётчика не получили** — владелец просил только хаб.

### Проверка (14.10.2026)

- Headless-Chrome с `?_ym_debug=1`, сетевой журнал (`--log-net-log`):
  `tag.js?id=113625003` → 200, в консоли `PageView. Counter 113625003`,
  хит `mc.yandex.com/watch/113625003` → 200, вебвизор `watch/113625003/1` отправлен,
  хитов в чужой счётчик нет, ошибок JavaScript нет.
- В отчётах Метрики тестовый визит не виден: headless-браузер отсекается фильтром
  роботов. Статус кода в API (`code_status`) Метрика обновляет сама, по расписанию;
  на момент проверки — `CS_ERR_UNKNOWN`.
